## 二、知识点记录

### 1. Dataset 与 DataLoader

- Dataset：组织和提供样本，可根据索引取得数据。
- DataLoader：负责按批次加载数据、迭代数据，并可控制是否打乱顺序。
- TensorDataset(X, y)：把输入样本与对应标签配对。

### 2. DataLoader 常用参数

- batch_size：每个 Batch 包含的样本数。
- shuffle=True：每轮迭代时打乱样本顺序，训练集通常使用。
- drop_last=False：保留最后一个不完整 Batch；初学和一般验证场景通常不丢弃。

首次小实验：10 个样本，batch_size=4，drop_last=False，实际得到 3 个 Batch，样本数依次为 4、4、2。终端输出形状依次为 (4, 2)、(4, 2)、(2, 2)，标签形状依次为 (4, 1)、(4, 1)、(2, 1)。

### 3. Batch、Iteration 与 Epoch

- Batch：一次送入模型的一批样本。
- Iteration：处理一个 Batch 的一次训练迭代；本次训练循环中每个 Batch 更新一次参数。
- Epoch：完整遍历一次训练集。

当不丢弃最后一个不完整 Batch 时：

\[
\text{Iterations per Epoch}=\left\lceil\frac{N}{\text{batch\_size}}\right\rceil
\]

### 4. 数据集划分与 MLP 训练

本次实验使用合成数据：

- X = torch.randn(100, 2)
- y = X[:, 0:1] + 2 * X[:, 1:2]
- 使用 random_split 将 100 个样本划分为 80 个训练样本、20 个验证样本。
- train_loader：batch_size=16，shuffle=True，共 5 个 Batch。
- val_loader：batch_size=16，shuffle=False，共 2 个 Batch。

模型结构：

\[
2 \rightarrow 4 \rightarrow 1
\]

即 nn.Linear(2, 4) → ReLU → nn.Linear(4, 1)。

损失函数：nn.MSELoss()。  
优化器：Adam，learning rate = 0.01。  
训练轮数：20 Epoch。

### 5. 训练与验证模式

- model.train()：切换到训练模式；会影响 Dropout、BatchNorm 等层的行为，本身不负责执行参数更新。
- model.eval()：切换到评估模式；本身不负责计算验证损失，也不自动关闭梯度。
- torch.no_grad()：在代码块内停止记录梯度计算过程，适合验证和推理阶段。
- 验证阶段只用当前模型参数计算预测与损失，不调用 backward() 和 optimizer.step()。

### 6. 模型与损失函数的调用关系

`model = MLP()` 创建 MLP 类的实例；`model(X_batch)` 调用该实例，PyTorch 会通过模块调用机制执行 forward()。日常推荐写 `model(X_batch)`，而不是直接调用 `model.forward(X_batch)`。

损失函数也采用“先创建对象，再传入数据调用”的方式：

```python
criterion = nn.MSELoss()
loss = criterion(prediction, y_batch)
```

也可以写成 `nn.MSELoss()(prediction, y_batch)`，但训练循环中通常先创建并复用 criterion。不能把 `nn.MSELoss(prediction, y_batch)` 当成标准调用方式，因为 nn.MSELoss(...) 这一步是创建损失函数对象，不是传入预测值和标签计算损失。

## 三、实战结果

### 1. DataLoader 小实验

- 10 个样本，batch_size=4。
- 成功输出三个 Batch，大小分别为 4、4、2。
- 输入与标签的 Batch 维度匹配，程序无报错。

### 2. MLP 训练实验

程序成功运行 20 Epoch，训练损失和验证损失均持续下降。

| 指标 | Epoch 1 | Epoch 20 |
|---|---:|---:|
| Train Loss | 5.598103 | 0.053713 |
| Val Loss | 5.460529 | 0.033922 |

观察结论：

- 训练损失明显下降，模型逐渐拟合训练数据。
- 验证损失也明显下降，当前实验没有出现“训练损失下降、验证损失持续上升”的典型过拟合信号。
- 这是一个简单合成线性数据实验，能验证训练流程正常工作，但不能当作真实任务上的泛化能力证明。

## 四、理解检查

用户能正确说明：

1. 验证阶段使用当前模型参数评估效果，不进行参数更新。
2. Train Loss 下降而 Val Loss 上升，可能是过拟合（Overfitting）的表现。

对调用关系进一步澄清：

- `model(X_batch)` 是调用已创建的 MLP 模型实例，并执行 forward 流程。
- `criterion(prediction, y_batch)` 是调用已创建的 MSELoss 实例来计算损失。
