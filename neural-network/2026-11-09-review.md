### 模块 1：Tensor、MLP 与前向传播

练习文件：`review_01_mlp.py`（本机 VS Code 文件，本次未上传源代码）

用户独立完成：

- 使用 `torch.tensor()` 创建输入 X 和标签 y。
- X 形状为 (3, 2)，y 形状为 (3, 1)。
- 定义 MLP 类，结构为 `Linear(2, 4) → ReLU → Linear(4, 1)`。
- 实现 `forward()`，执行前向传播。
- 创建模型对象，调用 `model(X)` 得到预测，并使用 `nn.MSELoss()` 计算损失。

理解检查：

- 若第一层改为 `Linear(2, 8)`，下一层需要相应改为 `Linear(8, 1)`，因为相邻层维度必须匹配。
- 删除 ReLU 后程序仍可运行，但连续 Linear 层的组合仍是仿射变换，缺少非线性表达能力。
- 即使网络含有 ReLU，最后一个 Linear 层仍可能输出负数；ReLU 不保证最终预测值非负。
- 讨论了网络深度（Depth）、宽度（Width）、Epoch 和 Iteration 的区别，以及 ReLU 网络通过分段线性函数近似非线性关系的直觉。

### 模块 3：Autograd、梯度与参数更新

复习了标准更新顺序：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

用户能够正确解释：

- 不调用 `zero_grad()` 时，梯度会累积。
- `loss.backward()` 负责计算梯度，不会直接更新权重。
- `optimizer.step()` 根据梯度更新优化器管理的可训练参数，例如 Linear 层中的权重和偏置。

### 模块 4：train、eval、no_grad 与 Dropout

练习文件：`review_03_mode.py`（本机 VS Code 文件，本次未上传源代码）

实验设置：

- `dropout = nn.Dropout(p=0.5)`
- `x = torch.ones(1, 8, requires_grad=True)`

实际观察结果：

1. `dropout.train()`：重复前向计算时，元素会随机置零；保留元素按倒置 Dropout 规则缩放，因此示例中可见 0 和 2；输出仍记录梯度。
2. `dropout.eval()`：Dropout 不再随机丢弃，输出恢复为全 1；`requires_grad` 仍为 True。
3. `dropout.train()` 配合 `torch.no_grad()`：仍然执行随机丢弃，但输出的 `requires_grad` 为 False。

用户正确回答：eval() 不会自动关闭梯度记录，因为输入设置了 `requires_grad=True`，且没有使用 `torch.no_grad()`。

核心结论：

- `model.train()` / `model.eval()` 控制模块的训练或评估行为，例如 Dropout、BatchNorm。
- `torch.no_grad()` 控制是否记录梯度计算。
- 两者互不替代。常见验证/推理写法是 `model.eval()` 配合 `torch.no_grad()`。

### 模块 5：完整 MLP 训练与评估综合实战

练习文件：`review_04_full_training.py`（本机 VS Code 文件，本次未上传源代码）

任务设置：

- 合成数据：100 个样本，每个样本 2 个特征。
- 目标关系：`y = X[:, 0:1] + 2 * X[:, 1:2]`。
- 数据划分：训练集 70、验证集 15、测试集 15。
- Batch Size：16。
- 模型：`Linear(2, 4) → ReLU → Linear(4, 1)`。
- 损失函数：MSE。
- 优化器：Adam，学习率 0.01。
- 训练轮数：30 Epoch。

#### 调试过程与关键发现

第一次运行时，训练循环直接使用了 `model(X)`，没有迭代 `train_loader`：

- 这导致 100 个样本（包括验证集和测试集）都参与了训练，验证和测试结果不再独立。
- 每个 Epoch 只有一次参数更新，30 Epoch 总计 30 次更新。
- 后来改为在 Epoch 内遍历 `train_loader`，每个 Batch 单独清空梯度、前向传播、反向传播和更新参数。

随后又发现验证循环缩进在 Epoch 循环之外，导致验证损失只在训练全部结束后计算一次。将验证循环移入 Epoch 循环、放在训练 Batch 循环之外后，才能逐 Epoch 观察 Train Loss 和 Val Loss。

这次调试重点说明：Python 缩进会决定循环嵌套层级；训练、验证和测试必须使用各自的数据子集，不能把验证集或测试集混入训练。

#### 最终正确流程的运行结果

| 指标 | Epoch 1 | Epoch 30 / 最终 |
|---|---:|---:|
| Training Loss | 5.887768 | 0.040270 |
| Validation Loss | 3.891537 | 0.035808 |
| Test Loss | — | 0.027175 |

观察结论：

- Training Loss 与 Validation Loss 随训练推进明显下降。
- 最终 Test Loss 也较低，说明本次简单合成任务上的拟合效果较好。
- 三个数据集样本量较小，且本次实验没有记录固定随机种子；具体 Loss 会受随机数据、数据划分和模型初始化影响，不应把这些数值视为每次运行都必须复现的固定结果。
- 测试集应只用于最终评估，不应用测试结果反复调整超参数。
